Time & Space Complexity Justification

1. Linear Search per Partition: \(O(k)\)

At each recursive invocation with a subtree of size \(k\), the algorithm identifies the left child root from preorder (\(\text{preorder}[\text{pre\_start} + 1]\)) and performs a linear search for its index in the postorder segment.

\[ T_{\text{search}}(k) = O(k) \]

Because we intentionally use a linear search (preserving textbook clarity without hash map lookup overhead), scanning up to \(k\) elements incurs proportional work at every subtree.

2. Worst-Case Time: \(O(n^2)\)

Under the Full Binary Tree assumption, every internal node has two children. In a highly unbalanced full binary tree (such as a comb-shaped tree where each internal node has one leaf child and one recursive subtree of size \(n - 2\)), the search range decreases by only two nodes per level:

\[ T(n) = T(n - 2) + O(n) \] \[ T(n) = O(n^2) \]

Expanding the arithmetic summation \(\sum_{i=0}^{(n-1)/2} O(n - 2i)\) demonstrates how the linear search dominates execution time in unbalanced full binary trees.

3. Best-Case Time: \(O(n \log n)\)

When the full binary tree is balanced, each partition step divides the elements into two subtrees of approximately equal size \(\approx n/2\):

\[ T(n) = 2T(n/2) + O(n) \] \[ T(n) = O(n \log n) \]

By Case 2 of the Master Theorem, solving this recurrence across \(\log_2 n\) levels with \(O(n)\) total search work per level yields \(O(n \log n)\).

4. Auxiliary Space: \(O(h)\) vs. Output Space: \(O(n)\)

The algorithm maintains only index boundaries, avoiding sub-array allocations. Memory is strictly separated into auxiliary stack frames and output tree storage:

\[ \text{Auxiliary Stack Space} = O(h) \] \[ \text{Output Tree Space} = O(n) \]

Auxiliary stack space is proportional to tree height \(h\): worst-case \(O(n)\) for unbalanced trees and \(O(\log n)\) for balanced trees. The \(O(n)\) output tree storage is accounted for separately.

Comparative Complexity Summary

Approach Worst-Case Time Best-Case Time Auxiliary Space Output Space
Base Recursive (Linear Search) \(O(n^2)\) \(O(n \log n)\) \(O(h)\) (recursion stack, \(h \le n\)) \(O(n)\) (tree nodes)
Hash Map Optimized \(O(n)\) \(O(n)\) \(O(n)\) (hash table + stack) \(O(n)\) (tree nodes)

Limitations & Structural Ambiguity

Ambiguity in Reconstruction

The algorithm treats the next element in preorder as the root of the left subtree (\(\text{preorder}[\text{pre\_start} + 1]\)). However, preorder and postorder traversals alone cannot uniquely determine the structure of every arbitrary binary tree.

For example, if a node has only one child, the traversals cannot establish whether that child belongs on the left or right.

Tree 1: Left Child

Pre: A B | Post: B A

Tree 2: Right Child

Pre: A B | Post: B A

To guarantee unique reconstruction, one of the following conditions must hold:

  1. Full Binary Tree assumption: Every node has either zero or two children. Under this assumption, and assuming distinct node values and valid traversals, the reconstruction is uniquely determined.
  2. Explicit null markers: Missing child positions are represented explicitly in the traversals, allowing arbitrary binary tree structures to be reconstructed.

Multi-Language Implementations

All four implementations in this repository share the exact same algorithmic structure, recursive boundaries, and input/output contract.

C (C99/C11)

Explicit memory management with malloc, free, recursive partition logic.

clang -O2 C/solution.c -o C/solution

C++ (C++17)

RAII smart pointers with std::unique_ptr<Node>, zero manual memory leaks.

clang++ -O2 -std=c++17 C++/solution.cpp -o C++/solution

Java (Java 8+)

Clean Node class, recursive indexing, exception handling for malformed input.

javac Java/Main.java && java -cp Java Main

Python (Python 3)

Idiomatic, clean reference implementation used by the unified test runner.

python3 Python/solution.py
